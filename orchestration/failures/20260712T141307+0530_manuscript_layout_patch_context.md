# Failure report

## Task

Reduce manuscript overfull boxes after the first successful LaTeX build.

## Failed command

An `apply_patch` update targeting several display equations in
`paper/main.tex` and the long PHM webpage entry in `paper/references.bib`.

## Error

`apply_patch verification failed: Failed to find expected lines` for the
relative-velocity equation.

## Files changed before failure

- `paper/main.tex` had already been created and successfully compiled.
- `paper/Makefile`, `paper/README.md`, `paper/evidence_map.md`, and
  `paper/references.bib` existed before this formatting update.
- `paper/build/**` and
  `reports/paper/semifab_cmp_poc_draft.pdf` were generated by the successful
  first build.
- The failed patch was rejected; it changed none of its target files.

## Read-only diagnosis

The expected context used `\omega_p` in every occurrence of the relative-speed
equation. Inspection of the actual source found one earlier transcription
error, `(omega_p-\omega_w)^2r^2`, with the leading backslash missing. LaTeX
accepted this as a sequence of ordinary math symbols, so the PDF built but the
displayed equation is scientifically incorrect at that term.

The successful build produced a 12-page PDF with resolved bibliography and
cross-references. Its log also reports large overfull boxes in the clock,
hydraulic, relative-speed, coupling-availability, warning-target, and long PHM
web-address lines. These are layout problems rather than compilation errors,
but the relative-speed transcription must be corrected before the PDF can be
accepted.

## Likely causes

1. The original bounded manuscript patch omitted a backslash in one occurrence
   of `\omega_p`.
2. The later multi-location formatting patch assumed the intended equation
   rather than matching the actual source, causing context verification to
   fail.
3. Several one-line equations and the long bibliography URL exceed a narrow
   two-column measure.

## Recovery options

1. Correct the missing `\omega_p`, split each affected display with aligned
   line breaks, replace the printed long URL with a short webpage description,
   rebuild, and rerun log/text/visual checks.
2. Correct only the scientific typo, accept the existing overfull layout, and
   rebuild.
3. Leave the generated PDF as an unaccepted draft and postpone manuscript
   completion.

## Recommended option

Option 1. It fixes the scientific transcription and produces a reviewable
two-column layout without changing any frozen result or claim.

## User decision required

Authorize Option 1 before further manuscript mutation.

## Resolution

Status: RESOLVED on 2026-07-12 after user authorization of Option 1.

- Corrected the relative-speed term from the unintended ordinary-symbol text
  `omega_p` to the intended `\omega_p`.
- Wrapped the clock, pump, hydraulic-balance, relative-speed,
  coupling-availability, and pending warning-target displays for the
  two-column measure.
- Shortened the printed PHM bibliography description while preserving the
  exact source URL in the BibTeX `url` field.
- Rebuilt with `conda run -n devkki make -C paper`; all LaTeX and BibTeX passes
  completed successfully.
- The final log contains no LaTeX warning, unresolved citation/reference,
  overfull box, or TeX error selected by the acceptance scan.
- The reviewed PDF is 12 A4 pages, contains all six generated evidence
  figures, and has SHA-256
  `855f71a9e40149fbfcf7ad29411802d6b4e3ab2de9056781f450acf911906773`.
- Extracted-text checks covered the evidence boundary, corrected kinematics,
  WP08/WP10 values, visibly pending protocols, limitations, conclusion, and
  bibliography. Representative pages 1, 4, 6, 7, 8, 9, and 11 were rendered
  and visually inspected for two-column layout, equations, figures, tables,
  pending labels, and references.
- `paper/build/main.pdf` and
