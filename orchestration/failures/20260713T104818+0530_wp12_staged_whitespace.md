# Failure report

## Task

Validate the staged WP12 implementation, evidence, governance, and manuscript
checkpoint before Git commit.

## Failed command

```text
git diff --cached --check
```

## Error

The staged diff reports trailing whitespace on four metadata lines in
`orchestration/reports/wp12_early_warning_validation.md` and on every row of
`reports/early_warning/wp12_dataset.csv` and
`reports/early_warning/wp12_predictions.csv`. The CSV diagnostics made the
command output extremely large; no commit was attempted.

## Files changed before failure

All intended WP12 code, tests, configurations, synthetic evidence, decisions,
failure records, governance files, running paper, LaTeX manuscript, and reviewed
PDF are staged. Raw PHM data, the user-supplied archive, local paper PDFs,
credentials, and private agent state are not staged. The complete suite passed
170/170 and governance passed before staging.

## Read-only diagnosis

`write_csv_atomic` opens files with `newline=""` and uses Python
`csv.DictWriter` without an explicit line terminator. Its documented/default
writer dialect emits CRLF (`\r\n`), confirmed by `sed -n l`. Git treats the
carriage return as trailing whitespace unless the path has the `cr-at-eol`
whitespace attribute. These CSV bytes are already frozen evidence: changing
line endings would change the recorded whole-file dataset hash and prediction
artifact bytes. The Markdown report uses intentional two-space hard breaks on
four metadata lines; those can be replaced with `<br>` without changing any
scientific result.

## Likely causes

1. RFC-style CRLF output from the standard-library CSV writer was not declared
   to Git as an accepted line terminator for these generated artifacts.
2. The formal report retained Markdown trailing-space line breaks even though
   the repository uses `git diff --check` as a gate.

## Recovery options

1. Preserve the frozen CSV bytes and hashes; add a narrowly scoped
   `.gitattributes` rule
   `reports/early_warning/*.csv whitespace=cr-at-eol`; replace the four report
   hard breaks with `<br>`; restage only those files and the failure record;
   then rerun the staged diff, governance, and hash checks.
2. Change the CSV writer to LF, regenerate artifacts, and update every affected
   hash/report. This is a larger evidence revision with no scientific benefit.
3. Commit with the whitespace gate failing. This would weaken the checkpoint
   and is not recommended.

## Recommended option

Option 1. It preserves exact frozen evidence while making the repository's
line-ending policy explicit and fixes the actual Markdown whitespace.

## User decision required

Resolved. The user authorized option 1. The scoped Git attribute now recognizes
CR as part of the generated CSV line terminator, the four Markdown hard breaks
use `<br>`, and the staged diff/governance/hash checks are rerun before commit.
