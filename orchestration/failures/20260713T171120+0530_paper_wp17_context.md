LaTeX manuscript during Phase 3 closure.

An `apply_patch` update to the `WP17--WP18: integrated paired evaluation`
subsection in `paper/main.tex`.

match the manuscript's actual line wrapping. The attempted patch expected a
line beginning `runtime/controller latency,`; the file contains
`safety-filter rejections, attribution accuracy, prediction/controller latency,`.

tests, governance updates, architecture/plan/charter updates, modelling notes,
and earlier reviewed portions of `docs/running_paper.md` and `paper/main.tex`
were already changed before this command. The failed patch itself changed no
file. `git diff --check` remained clean immediately after the failure.

## Read-only diagnosis

The first intended replacement block is present exactly. The second block is
scientifically unchanged but has different source wrapping and includes the
prefix `prediction/` before `controller latency`. This is a patch-context
mismatch only; there is no LaTeX, model, test, data, numerical, permission, or
repository-content conflict.

## Likely causes

- The patch was composed from an earlier excerpt with truncated or normalized
  wrapping.
- The intended replacement combined two independently matchable paragraphs
  into one atomic patch, making an otherwise harmless line difference fatal.

## Recovery options

1. Apply two small, context-verified replacements using the exact paragraphs
   printed by the read-only diagnosis, running `git diff --check` after each.
2. Leave the WP17--WP18 manuscript subsection stale while the authoritative
   controller/safety decisions remain correct elsewhere.
3. Revert the earlier manuscript additions and defer all paper synchronization

## Recommended option

Option 1. It is bounded, preserves the completed scientific work, and updates
the manuscript without changing any model, contract, interface, schema, data,
or result.
